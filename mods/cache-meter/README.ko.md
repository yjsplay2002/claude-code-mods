# cache-meter

[English](README.md) · 한국어

이번 세션이 프롬프트 캐시를 얼마나 잘 쓰고 있는지(만료까지 남은 시간, 적중률, 캐시로 아낀
토큰, 캐시를 다시 쓴 횟수)를 status 줄에 보여주는 Claude Code mod입니다. 대화를 계속 끌고 가는 것보다 compact하는 게 더
싸지면 프롬프트 위에 **compact** 버튼이 나타납니다. 자동 compact(`idle`, 기본으로 켜짐)는
자리를 비운 사이 캐시가 곧 만료될 때 알아서 compact합니다.

status 줄 (항상):

```
● 캐시 42m 남음 (1h)  │  적중 97% (세션 94%)  │  캐시 절약 ≈3.1M  │  캐시 깨짐 1회 (컨텍스트 재작성)  │  ctx ██░░░░░░░░ 21% 214k/1.0M  │  자동 compact 모드: 자리 비울 때만
```
status 줄은 기본이 영어이고, `language`를 `ko`로 두면 위처럼 한국어로 나옵니다. compact 직후 다음 응답 전까지는 `◇ compact됨 (cache-meter, 7m 전) · 첫 응답 대기`로 바뀌고, compact 없이 캐시가 만료되면 끝에 `· compact 안 됨`이 붙습니다.


프롬프트 위 (compact가 이득일 때만):

```
[ compact (≈-109k) ]  7턴이면 본전, 계속하면 ≈109k 절약 · ctx 214k→44k   자세히
```

Claude Code v2.1.287 이상(mod 지원)이 필요합니다.

## 왜 만들었나

긴 Claude Code 세션의 비용(구독이면 한도 소모)은 대부분 프롬프트 캐시가 어떻게 동작하느냐로
정해집니다. 캐시가 살아 있으면 컨텍스트를 0.1× 가격으로 다시 읽지만, 캐시가 식으면 다음
메시지가 컨텍스트 전체를 1.25~2× 가격으로 다시 씁니다. 그런데 작업하는 동안 이 비용은
눈에 보이지 않습니다.

기존 도구들은 각자 일부만 다뤘습니다. `claude-code-usage-bar`(TTL 기본값이 5분이라 1시간
캐시를 쓰는 구독 사용자에겐 맞지 않음), `claude-code-statusline`, `claude-vibeline` 같은
상태줄, `agentmeter`, `claude-lens` 같은 사후 분석 대시보드, 모든 트래픽을 서드파티 코드로
거치게 하는 로컬 프록시 등입니다. 하지만 어느 것도 *"지금 이 대화를 compact하는 게 계속
끌고 가는 것보다 싼가?"* 라는 실제 질문에는 답하지 않았습니다.

cache-meter는 Claude Code mod로 만들어서, Claude Code가 직접 알려주는 캐시 상태와 사용량
한도를 읽고 그에 따라 행동합니다.

- 캐시가 살아 있는지, 얼마나 남았는지, 식으면 다음 메시지에 얼마가 드는지 한눈에 봅니다.
- compact가 실제로 토큰을 아낄 때만 손익분기 턴 수와 함께 **compact** 버튼이 뜹니다.
  자리를 비웠는데 캐시가 곧 만료되려 할 때는 자동 compact가 대신 처리합니다.

## 설치

Claude Code 터미널 세션의 프롬프트에서:

```
/plugin install cache-meter --marketplace yjsplay2002/claude-code-mods
```

marketplace 추가를 물으면 `y`, 그다음 범위(scope)를 고릅니다(기본값은 user, 모든 프로젝트에 적용).

셸에서:

```
claude plugin install cache-meter --marketplace yjsplay2002/claude-code-mods
```

`/plugin`이 안 되는 데스크톱 앱에서는 프롬프트 옆 + → Plugins → Add marketplace에
`yjsplay2002/claude-code-mods` 입력 → Add plugin 순서로 설치합니다.

## 무엇을 보여주나

- **캐시**: 메인 대화의 프롬프트 캐시가 만료되기까지 남은 시간과 TTL(5m
  또는 1h). `●` 살아 있음, `⚠` 곧 만료, `✕` 만료됨(다음 메시지가 다시 쓸 토큰 수 표시).
  캐시를 읽는 요청이 있을 때마다 타이머가 다시 차므로, 손을 놓고 있을 때만 줄어듭니다.
- **적중률**: 마지막 요청과 세션 전체에서 입력 중 캐시에서 읽은 비율.
- **절약**: 이번 세션에 캐시 덕분에 아낀 입력 토큰 환산량(읽기 0.1×, 쓰기 할증은 차감).
- **재작성**: 직전 요청이 캐시해 둔 앞부분을 다시 써야 했던 요청 수.
- **컨텍스트**: 다음 요청이 다시 보낼 양 / 모델의 컨텍스트 창.

사용량 한도는 다른 도구에 맡깁니다.

`/cache-meter`는 상세 내역, 비용 비교, 버튼이 있는 창을 엽니다. `c` 지금 compact, `a` 자동
모드 순환, `b` status 줄 숨김/표시(`/cache-meter band`로도 가능).

## 언제 compact를 추천하나

비용은 입력 토큰 환산으로 계산합니다. Anthropic의 기본 입력 가격 대비 배율인 캐시 읽기 0.1×,
캐시 쓰기 1.25×(5m) 또는 2×(1h), 출력 5×를 씁니다. 구독 한도도 같은 가중치로 줄어듭니다.

앞으로 *N*턴(기본 15) 동안을 비교합니다.

- **유지**: 매 턴 컨텍스트 전체를 캐시에서 다시 읽습니다.
- **지금 compact**: 요약기가 컨텍스트를 한 번 읽고 요약을 씁니다(출력 가격). 다음 턴이 요약을
  캐시하고, 이후 턴은 더 작은 컨텍스트를 읽습니다.

세 가지 상황을 구분합니다.

| 상황 | 유지 비용 | compact가 이길 수 있는 이유 |
| --- | --- | --- |
| 작업 중 (캐시 살아 있음) | N × 0.1 × 컨텍스트 | 이후 턴마다 덜 읽음 |
| 곧 만료 (대기 중, 캐시 만료 임박) | 돌아왔을 때 전체 재작성 | 요약기는 아직 살아 있는 캐시를 읽음 |
| 만료됨 (캐시 식음) | 다음 메시지에서 전체 재작성 | 이후 턴마다 덜 읽음 |

컨텍스트가 80k 토큰 이상이고 절약이 입력 토큰 환산 40k 이상일 때 추천합니다. 요약 길이는 이
PC에서 실제로 compact한 결과로 학습합니다. compact는 요약이라 세부 내용이 빠질 수 있습니다.
세부가 중요한 디버깅 중이라면 컨텍스트를 유지하세요.

## 자동 compact

`/config`(cache-meter → Auto compact), `/cache-meter auto off|idle|always`, 또는 창의 `a`
버튼으로 바꿉니다.

- `off`: 하지 않음.
- `idle` (기본값): 턴이 실행 중이 아니고, 90초 동안 입력이 없고, 캐시가 곧 만료될 때만(1h는
  8분 미만, 5m은 75초 미만 남았을 때).
- `always`: 위에 더해, compact가 추천 상태이고 세션이 90초 동안 대기 중일 때도.

Claude Code 자체 idle compaction(2.1.299+)도 1시간 캐시가 만료되기 전에 200k 이상 대화를
compact합니다. `idle` 모드는 이를 더 작은 컨텍스트와 5분 캐시까지 넓힙니다.

## 설정

| 항목 | 기본값 | 의미 |
| --- | --- | --- |
| `autoCompact` | `idle` | `off`, `idle`, `always` |
| `horizonTurns` | 15 | 비교에 쓰는 앞으로의 턴 수 |
| `minContextTokens` | 80000 | 이보다 작은 컨텍스트에선 추천 안 함 |
| `minSavingTokens` | 40000 | 이보다 적게 아끼면 추천 안 함 |
| `ttl` | `auto` | `5m` 또는 `1h`로 고정. `auto`는 요금제와 캐시 동작으로 추정 |
| `inputUsdPerMTok` | 0 | 모델의 입력 가격(USD/백만 토큰). 넣으면 달러로도 표시 |
| `language` | en | status 줄 언어: `en` 또는 `ko` |
